## 2. 改了什么（commit d810498，10 文件 +771/-275）

### 线1 特征提取（根因 #1，连带 #5 难度 / #6 质量评分）
- **根因**：`feature_extractor.py` 的 v3 三合一巨型 prompt（难度6维+质量6维+教学，29字段）→ deepseek 是推理模型，reasoning 放飞**吃满整个 max_tokens、output=0、finish=length**。实测 8192/16384 全吃满，**调 reasoning_effort 无效、抬 max_tokens 无效**（见 memory `reference_reasoning_model_budget`）。→ 95% 落 `DEFAULT_FEATURES`（working_memory=3…），雷达图拉平、难度失真、无 quality_score。

  - **length 重试**：组内首发 length → 重试 1 次 → 仍 length 则该组降级 + JSONL warning。
  - `llm_config.py`：新增 `FEATURE_SPLIT_PURPOSES` 提额白名单（=16384，**绝不超 16384**=provider 上限）。
  - `feature_cache.py`：版本 `v3-20260530`→`v4-20260615-split`，作废旧 schema 缓存。
- **改动文件**：`feature_extractor.py`（+741/-275，含删旧单任务 `_extract_features_uncached` 约235行 + 死函数 `build_compact_feature_retry_prompt`）、`llm_config.py`、`feature_cache.py` + 3 新 prompt。

## 8. 操作纪律（本会话教训）

- **ssh 只用短连接**（`-o ConnectTimeout=10`）；后台任务 = detached + 反复短 ssh 轮询，禁单条长连接。
- **不主动轮询 harness 后台任务**（Workflow/Bash run_in_background）→ 等结构化 `<task-notification>`（自带结果）。jdcloud 上的 detached 进程 harness 不追踪，才需自己短 ssh 轮询。
- 本机文件系统偶发卡（watcher 重扫）→ 优先 jdcloud 侧操作或等扫完。
- 复杂代码外科手术 / 迭代调测 → 派 executor agent（它能跑容器 pytest 迭代）。
- prompt 调优本质多轮 + 模型可能顽固抹平权重 → 改对层级（用 `analysis_service` 看数据流）比盲调 prompt 重要。
