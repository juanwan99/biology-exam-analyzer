## 目标 A：报告学科断点（原 Goal 2 收尾）

### A1 — report_insights 取 subject 键路径错（核心，单行根因）

**现象**：非生物科报告生成时日志打印 `[LLM分析] 开始生成 mode=full subject=biology`（实查 geography 卷复现，subject 应为 geography 却是 biology）。

**根因（已钉死）**：
- 写入方 `backend/report_data.py:621-634`：`aggregate_report_data` 正确算出 `report_subject`（优先 exam_info.subject，回退首题 subject，normalize 兜底）并写进 **`rdata["exam_info"]["subject"]`**。
- 读取方 `backend/report_insights.py:758`：`_subj = normalize_subject(data.get("subject"))` —— 读的是 **顶层 `data["subject"]`**，取不到 → `normalize(None)` → 回退 `biology`。
- 连带 `backend/report_insights.py:114` 与 `:182` 的教研员/教师 prompt 用 `get_subject_name(data.get("subject"))` → **8 个非生物科报告的执行摘要、教学建议以「生物教研员/生物教师」身份生成**。
- **影响边界**：仅 LLM 散文文字（身份语境错）；维度结构 / 雷达图 / 细分数据不受影响（走 competency_summary，subject 正确）。

**修法（二选一，推荐方案 1）**：
- **方案 1（改读取方，推荐）**：report_insights.py 里**全量**把取 subject 的点统一成
  `(data.get("exam_info") or {}).get("subject") or data.get("subject")` 再 normalize。
  务必先 `grep -n 'data.get("subject")' backend/report_insights.py` 找全所有点（至少 758/114/182，可能还有别处），逐一改，不要漏。
- **方案 2（改写入方）**：report_data.py 在 rdata **顶层也补一份** `"subject": report_subject`（与 exam_info.subject 同源），让 report_insights 顶层读得到。
- 二选一即可，保证「写入键」与「读取键」对齐；不要改成两边仍不一致。

### A2 — per_subject_e2e.py leak 检测误报（测试可信度）

**现象**：`per_subject_e2e.py` 报 english `leak=['逻辑推理']`、politics `leak=['社会责任']`，导致显示 3/5 FAIL。

**根因（已确认是测试逻辑缺陷，非产品 bug）**：`backend/per_subject_e2e.py:44-51` 用「其他科顶层维度名」在**整个 HTML 做子串匹配**，撞上了合理的**细分子能力**——英语「思维品质」细分含「逻辑推理」、政治「公共参与」细分含「社会责任」，二者都出现在 `"细分":{...}` 的 JSON 数据段里（各仅 1 次），被误判为跨科泄漏。**产品维度其实全对（dims_in_html 全 4/4、5/5、6/6）**。

**修法**：leak 检测排除结构化细分区——只在**雷达图维度标签 / competency 维度表展示区**检测「其他科顶层维度名」，不在 `"细分"/distribution` 的 JSON 明细段做全文子串匹配。
